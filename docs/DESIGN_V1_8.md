# V1.8 阅读与知识使用设计

## 实际默认路径

普通笔记、网站/视频收藏、工具仍先打开本地预览，完整阅读/编辑与外部网站访问独立；综合文档主体直接阅读，另有概要预览。没有采集的网页/视频正文不会被制造出来。新增能力接在原阅读器、关系、来源和导入内核中，不增加第二知识库或 AI 引擎。

阅读操作栏固定显示返回、当前标题、适用的阅读/整理模式、编辑、置顶与更多；跨内容引用跳转后可“返回上一内容”。长标题省略并保留完整提示。列表筛选/排序/页码/滚动沿用 V1.7.3，新的领域/专题导航仍使用新的意图，不复活旧条件。

## 真正独立的三栏

ReaderPanels 将大纲、正文、辅助信息作为兄弟区域。左标题有收起按钮，收起后左侧缘显示“大纲”；右标题有关闭按钮，收起后右侧缘显示“来源·关联”。顶部不再有这两个面板的主要开关。

1920/1366px：左右各自约185～205px/280～300px，正文利用剩余宽度。正文单独滚动，长文阅读不移动左右栏；大纲和辅助正文各自滚动。切换来源/关联/AI标签不会重置正文位置。左右选择独立，任何宽度下不会因打开一侧或切换模式自动关闭另一侧。

≤1000px：面板按需覆盖正文两侧；390px同时打开时各占约44%/48%视口，关闭按钮始终可达，原正文保留完整宽度在背后。关闭任意面板不改变另一侧选择。窄屏默认大纲收起，先保证正文，用户可以明确同时展开。全局侧栏仍可使用，不与章节大纲合并。

大纲层级、标题、顺序、稳定章节 UUID 不变；定位使用正文滚动容器的实际顶部。滚动跟踪高亮章节。会话保存左右开合、辅助标签、大纲分支、展开章节、当前章节和正文位置；显式章节/摘录定位优先于普通位置恢复。刷新和引用跳转均从真实记录重新加载。

## 划词与人工记录

仅在真实 `.prose[data-reading-id]` 正文内的单一选区显示工具栏，跨两份正文、空白、编辑器输入框不触发。有效选区2～2000字符，复制、添加批注、引用到笔记、建立关联和上下文AI为五个紧凑动作。Escape先取消选区，不误关阅读器；正常 Ctrl+C 和拖动不被拦截。

个人批注保存摘录、当前内容/章节ID、原来源标题与所属页面快照、前后文定位、评论、修订和创建时间。来源面板可查看、编辑、删除、定位；编辑采用修订校验，不覆盖另一窗口的新修改。删除仅标记记录，不改原文或已追加的引用正文。未保存评论关闭会确认，刷新保护真实修改。

引用可新建普通笔记，或追加到已有普通笔记/综合文档/知识块的实际正文。保存前展示原摘录和目标；服务端重新校验来源选区指纹、目标正文版本与未保存草稿。正文追加、上一版历史和引用记录同事务；出错全回滚。附带来源标题/稳定ID、章节ID、引用创建时间和可复制的 `#quote-引用UUID` 链接。引用不会把原文或AI推断升级为人工确认；综合知识的旧confirmed正文被追加后回到review。

引用正文的 `data-entry-id` 继续参与原确定性正反向引用；`data-reading-mark` 只补充精确定位，Tiptap和HTML清理白名单显式保留。关系面板可看到反向引用及摘录证据，无第二关系数据库。原七种方向、候选确认、防循环、删除保护与历史不变。

## 锚点策略与失效

锚点 v1 = 稳定来源内容/章节ID + 规范正文 SHA-256 + 精确摘录 + 起止位置 + 各64字符前后文。

- 正文指纹相同且当前位置原文一致：标记“原版本可定位”。偏移只在这个条件下使用。
- 正文变化：搜索完整摘录，必须前后文吻合且唯一才标记“前后文唯一匹配”；前方新增不改变原上下文时仍能定位。
- 摘录被改、删除、上下文变化或有多个匹配：保留原摘录，显示定位失效/待重关联，按钮禁用；深链接也提示无法可靠定位，不高亮其他文字。
- 章节改名、重排不改变ID；当前归属通过真实parent计算，历史归属快照仍保留。恢复与原指纹相同的历史正文后可以恢复精确定位。
- 客户端高亮前再次按当前DOM文字核验同一策略，使用Edge的CSS Highlight，不插入改变正文语义的标记。

这是一种保守、可解释的文本引用锚点，不承诺任意大规模改写后自动重绑。失效后人工重新选择建立新记录，旧摘录可保留或明确删除；不静默修改原锚点。不存在原文时仍可阅读保存的摘录。删除引用记录后的正文链接会明确提示并保留来源供人工查看。

## 选区关联和 AI

选区“建立关联”打开原 RelatedPanel，用户搜索真实对象/章节、选择七类方向、填写理由和确认；选中文字作为来源端的实际证据，服务端按已有规则重验，AI候选不会自动确认。

选区AI使用原 ContextAssistant/Assistant，仅预填选中原文作为问题素材，默认真实来源ID作为证据。进入界面不调用模型；仍有完整范围、字符/Token/参考费用、主动费用确认、取消和错误提示，不自动保存回答。选区超过800字时AI入口要求缩小选区，避免无提示截断原有1000字问题预算。失败/取消保留当前问题与素材，Provider/模型/Endpoint/超时/限额/DPAPI未改。

## 简洁粘贴收纳

入口：全局“＋新建”→“粘贴文字 / Markdown”。选择解析格式、普通笔记/综合文档、来源性质与用户来源说明，再本地解析。纯文本整份保留；Markdown只按明确标题组织章节，不让AI猜测层级，也不自动访问ChatGPT历史。用户可逐项选择、改标题、设已有领域/标签/专题，返回修改格式/类型后再解析。

解析支持标题、段落、平面有序/无序列表、块引用、HTTP(S)链接、加粗和代码文字。原始HTML按文字转义，代码围栏中不拆标题。复用现有Tiptap可表示的格式；复杂表格/嵌套列表等按安全文字降级，完整原始文本仍在来源excerpt/导入包快照中。无明确标题的文档保留为单篇综合正文，不猜多条知识。

服务端将确定结构转换为内部JSON v2包，使用原短期预览/Schema、分类ID、来源日期、树结构、事务导入和历史追溯。原始粘贴全文存入source excerpt，JSON快照含该原文，不依赖前端临时状态。ChatGPT仅用户说明，epistemic=ai_inference/status=review；未知原始日期/作者留空，记录时间只是收纳时间。

重复检查在本地：标题规范化、已有网址及正文片段产生候选，不据此合并。预览标题编辑后、保存前重新查重；服务端提交再检查新数据。用户可新标签页查看已有、返回修改、勾选“仍另存”；相同原包继续按原导入hash要求明确另存。新条目有新ID，旧内容不改。全部批量新增同事务，缺父级/无效分类/注入故障不会留下半份内容。

限额：原始文本100000字符且≤256KiB，原协议包≤512KiB，最多100项/99章节、8层，预览最多8份/15分钟。超限明确拒绝，不截断。部分章节必须包含被选父级。

## 数据变化与验证

schema9→10仅追加 `reading_marks` 一表及两个索引，33张旧表不改。字段包含来源/目标外键、原文/定位快照、评论/修订、时间与软删除。启动和ZIP验证新增记录形状、锚点/大小/日期与外键；定位失效属于可保留业务状态，不是数据库损坏。活跃批注/引用保护源、目标及原所属页面不被回收；正文内引用仍由旧保护检查。

顺序迁移在持有原数据身份锁后执行，迁移前ZIP完整验证，失败回滚9；旧1～9备份严格校验再隔离向前恢复10，不降版本强开。DPAPI、用量、附件与草稿机制不变。正式资料前后核验和实际ZIP恢复结果见 TESTING。
