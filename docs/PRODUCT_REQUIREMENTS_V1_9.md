## 一、核心产品目标

为个人知识收藏馆新增一种正式内容类型：**思维导图**。

当前软件主要通过文字记录灵感、知识和想法。但用户在构思游戏系统、研究技术方案、梳理知识关系时，往往还没有形成完整的文字叙述。

希望通过简洁的关键词、节点、空间排列和连线，先记录想法之间的关系，再逐步形成完整结构。

核心体验：

**新建导图 → 输入一个关键词 → 快速增加分支 → 拖拽调整 → 连接其他想法 → 关联已有知识 → 自动保存。**

用户无需先撰写完整说明。

思维导图必须成为知识库内正式、可编辑、可搜索、可备份的知识内容，而不是图片附件或孤立的外部工具。

## 三、技术选型

请调查并比较适合当前 React + TypeScript 项目的成熟开源可视化编辑方案，优先考虑：

- Mind Elixir：树状思维导图编辑。
- React Flow / xyflow：自由节点、连线和自定义交互。

必要时可调查其他更合适的成熟开源方案。

请特别核实：

1. 开源许可证及本地部署条件。
2. 对当前 React 19、TypeScript、Vite 的兼容性。
3. 中心主题与树状自动布局。
4. Tab、Enter 等快速节点编辑能力。
5. 节点拖拽与结构调整。
6. 跨分支自由关系线。
7. 撤销、重做、缩放、折叠。
8. 数据模型是否能稳定序列化、备份和恢复。
9. 是否依赖云端服务、账号或付费 API。
10. 集成后的维护复杂度。

**不要因为此前偏好 Mind Elixir 就锁死选型。**

应以最低合理工程复杂度实现高质量的实际编辑体验，而不是机械比较功能数量。

可以使用成熟开源库，避免重复制造画布、缩放和拖拽基础设施。

不引入需要付费才能正常使用核心编辑功能的依赖。

## 四、新建思维导图

在全局「＋新建」中加入明确入口：

**思维导图**

新建后进入独立编辑界面，默认创建中心主题并自动聚焦输入。

支持：

- 导图标题。
- 中心主题。
- 领域、标签、专题归属。
- 置顶。
- 最近编辑时间。
- 从知识库列表直接打开。
- 复制导图。
- 软删除、回收站、恢复。
- 搜索导图标题和节点文字。

知识库应当有清晰的思维导图类型标识。

不得把导图保存成普通富文本图片。

## 五、核心可视化编辑能力

### 1. 节点创建

至少支持：

- 创建中心主题。
- 创建子节点。
- 创建同级节点。
- 快速修改节点文字。
- 删除节点。
- 复制节点或分支。
- 节点展开与折叠。

关键快捷键：

- Tab：添加子节点。
- Enter：添加同级节点。
- F2 或双击：编辑节点。
- Delete：删除选中节点，必要时确认。
- Ctrl+Z：撤销。
- Ctrl+Y / Ctrl+Shift+Z：重做。

输入文字时不能因为快捷键而意外删除节点或切换焦点。

### 2. 节点移动

支持鼠标拖拽：

- 调整节点位置。
- 调整分支顺序。
- 将分支移动到其他父节点。
- 展开或折叠分支。

如果自动布局和自由拖拽存在冲突，请设计明确规则。

不能出现画面位置改变但保存后又无解释地恢复原状的情况。

### 3. 视觉导航

至少支持：

- 缩放。
- 拖动画布。
- 适应屏幕。
- 居中定位中心主题。
- 节点选中高亮。
- 大型导图中的视图定位。
- 合理的长文本换行与节点宽度限制。

### 4. 简洁视觉设计

延续知识收藏馆现有视觉风格。

要求：

- 节点简洁。
- 连线清晰。
- 不使用大量装饰性图标。
- 默认配色克制。
- 不强制每个节点显示复杂属性。
- 编辑操作尽量就近出现。
- 避免画布被工具栏占据。

支持少量基础主题、分支颜色及节点样式即可。

## 六、跨分支关系线

本轮必须支持**树状父子关系之外的独立关系连接**。

例如：

“角色成长”与“经济系统”属于不同分支，但两者存在依赖关系。

用户可以选择两个节点，建立一条额外连线。

要求：

- 跨分支连接。
- 可选关系说明或简短标签。
- 显示连线方向（如适用）。
- 删除关系线。
- 不改变两个节点原有的父子结构。
- 关系线能够随节点移动正确更新。
- 保存、重新打开后关系仍然存在。

需要明确区分两类关系：

**结构关系：** 父节点与子节点。

**补充关系：** 两个节点之间的自由连接。

不得混淆两者，也不应因新增自由连线造成树形循环。

## 七、思维导图与文字大纲

同一张导图支持两种编辑视图：

**思维导图视图 ↔ 文字大纲视图。**

大纲模式中应展示节点的父子层级，并支持：

- 添加节点。
- 修改文字。
- 调整缩进。
- 调整顺序。
- 删除节点。
- 返回思维导图视图。

两个视图必须使用同一份结构化数据。

不能产生两个独立版本、切换后丢失编辑。

自由关系连线在大纲模式中可以通过关联标记、数量或详情入口呈现，不要求强行转换成缩进层级。

## 八、关联已有知识

这是本轮最重要的差异化功能之一。

每个思维导图节点可以选择关联知识收藏馆中已有的内容：

- 普通笔记。
- 网站收藏。
- 工具收藏。
- 综合文档。
- 综合文档章节或知识点。
- 其他思维导图。

交互流程：

选中节点 → 关联知识 → 搜索已有内容 → 选择目标 → 保存关联。

要求：

1. 节点显示轻量的关联标识。
2. 点击关联标识能够打开目标内容。
3. 有明确返回当前导图的路径。
4. 不把目标内容全文复制进导图。
5. 原知识改名后仍通过稳定 ID 关联。
6. 原知识删除或进入回收站后给出合理提示。
7. 不允许产生无法识别的悬空链接。
8. 必要时可以取消关联。

还应支持：

**从已有知识创建新节点。**

用户搜索一篇笔记或综合文档后，可以将它直接插入导图，默认使用标题作为节点文字，并附带知识链接。

请优先复用现有知识 ID、搜索、阅读导航及关系能力。

注意：导图节点之间的自由连线不等于全局知识关系，不能未经用户明确操作就写入全局知识关联表。

## 九、自动保存与数据安全

思维导图支持可靠的自动保存。

要求：

- 修改后保存状态可见。
- 防抖自动保存。
- 编辑失败时保留本地未保存内容。
- 页面刷新后能够恢复。
- 不因快速连续拖拽或多次编辑造成旧请求覆盖新数据。
- 多窗口同时编辑需有版本或冲突保护。
- 关闭存在未同步修改的页面时给予适当提示。
- 至少支持可恢复的历史版本或明确的编辑恢复机制。

特别注意导图数据比普通笔记更加结构化。

必须保护：

- 稳定节点 ID。
- 父子层级。
- 兄弟顺序。
- 自由关系线。
- 关联知识 ID。
- 位置或布局数据。
- 折叠状态。
- 节点文本及样式。

不允许静默丢失任何一类核心信息。

## 十、与现有知识模型整合

目前项目使用 React、Express、SQLite 和知识内容统一 ID 体系，正式数据库为 schema10。

请调查最合适的实现方式。

原则：

- 不重建已有知识库。
- 不改变已有内容 ID。
- 不破坏已有文档章节、来源、批注、引用及关联。
- 新增必要的导图专用结构化存储。
- 尽量复用领域、标签、专题、置顶、回收站、搜索和内容历史。
- 明确区分思维导图内容与普通富文本内容。
- 不将画布 JSON 当作不受校验的任意脚本。
- 导图数据纳入既有 ZIP 备份恢复。
- 搜索能够覆盖导图内部关键词。

必要时可以安全升级 Schema，但必须使用现有迁移与备份机制。

## 十一、导入与导出

至少支持：

- 导出 PNG。
- 导出 SVG。
- 导出结构化 JSON。
- 导入本软件兼容的导图 JSON。
- 导出 Markdown 层级大纲。

导出内容应与实际节点结构一致。

对于跨分支关系线和关联的知识 ID，应在 JSON 中完整保留。

Markdown 大纲不能表示全部关系时，应明确说明其属于有损导出，不应承诺可以完整还原所有连线。

导入前应预览和校验；不能通过导入任意 JSON 覆盖现有正式导图。

## 十二、本轮不做

以下功能暂不列入强制交付：

- 多人实时协作。
- 云端思维导图同步。
- 复杂无限白板系统。
- 大量专业制图模板。
- AI 自动生成完整思维导图。
- AI 自动创造知识关系。
- 商业思维导图格式的全面兼容。
- 外部付费插件。
- 将导图扩展成完整的项目管理或任务调度软件。

优先把快速记录、树状编辑、自由连接和知识整合做扎实。

## 十五、最终验收目标

用户能够在知识收藏馆内完成：

1. 点击「＋新建 → 思维导图」。
2. 输入一个灵感关键词。
3. 连续使用 Tab 和 Enter 快速构建多个分支。
4. 拖拽节点调整结构。
5. 在两个不同分支之间添加关系线。
6. 将其中一个节点链接到已有知识。
7. 关闭并重新打开导图，所有编辑仍然保留。
8. 切换文字大纲继续整理。
9. 将导图导出为图片或结构化文件。
10. 后续通过知识库搜索找到这张导图。

**最终评价标准：用户能否用很少的操作，把尚未形成完整文字的灵感保存为清晰的可视化关系。**

请自主完成调查、实施、测试、修复和 Git 提交，最终一次性交付。无需中途人工验收，也不要自动启动下一个版本。
