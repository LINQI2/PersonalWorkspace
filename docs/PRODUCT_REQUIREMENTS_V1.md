# 个人知识收藏馆 V1.0｜产品规格与 Codex 开发指令

版本：V1.0（需求基线）  
日期：2026-10-12  
状态：产品需求确认；尚未开发、运行或测试

## 1. 项目定位

建设一个 **Windows 电脑本地优先** 的个人网络资源收藏与知识笔记网站。体验以现代、简洁、美观的**规则网格卡片资源导航站**为主，详细文字笔记为辅。用户手动粘贴网络链接和填写元信息；可独立撰写原创知识笔记。未来可以增加 AI 整理、多平台同步、图片参考库、在线公开展示，但 V1 不实现这些复杂模块。

### 已确认的产品选择
- 电脑本地优先；浏览器访问；暂不需要云端和账号。
- 手动粘贴网址；**禁止自动网页标题/封面提取**，包括隐式抓取；允许人工填写标题、简介、封面。
- 规则网格卡片为主，现代简洁资源导航风格；允许手动上传封面，没有封面时使用精心设计的分类默认封面。
- 领域分类、多标签、专题收藏夹并存；一个条目可关联多个领域、多个标签和多个专题收藏夹。
- 资源可以附带个人笔记；另可创建不含网址的原创笔记。
- 富文本编辑器支持标题、加粗、列表、链接、图片及基本撤销重做。
- 公开发布属于未来功能；V1 所有内容仅本地私人使用，不提供公网读取或“伪公开”入口。

## 2. 范围与优先级

### V1 必须完成（P0）
1. 首页：规则网格卡片、左侧或顶部领域导航、搜索与筛选、最近添加排序、空状态。
2. 收藏管理：手工输入 URL/标题；简介可选；手动上传封面可选；新增、查看、编辑、删除（删除二次确认）；原网站打开操作单独可见。
3. 原创笔记：无 URL 也能建立条目；收藏卡片可附带个人富文本笔记。
4. 分类：领域可管理、支持多选；标签可增删与多选；专题收藏夹可创建、改名、删除与收录多个条目。删除分类或收藏夹不应连带删除条目。
5. 待整理：新增时可不选任何分类，自动进入待整理；可从待整理移出。
6. 查找：标题、简介、笔记文本的关键词检索；按领域/标签/专题收藏夹筛选；至少支持最近添加排序。
7. 展示：统一卡片宽高和图片区域比例；没有封面使用不依赖外部服务的本地默认图形；不同来源或内容类型有清晰轻量标识。
8. 数据：SQLite 持久化；图片存于本地附件目录；重启服务与浏览器后保留全部收藏、标签和图片。
9. 备份恢复：导出含数据库一致性快照和全部附件的压缩包；验证导入包结构与版本；恢复前自动备份当前数据；恢复操作显式二次确认；至少完成一次自动化或可重复的真实恢复演练。
10. Windows 一键启动：可在安装好必要运行环境后双击启动脚本，在同一 localhost 端口提供构建后的网页与 API；启动失败应有可理解的报错；说明如何停止。
11. 基本质量：表单校验、重复链接提示（允许用户决定是否保留）、错误提示、空状态、加载状态、基础自动化测试以及真实浏览器关键流程验证。

### V1 推荐完成（P1，不能影响 P0 交付）
- 置顶和最近更新排序。
- 深色/浅色主题切换并记忆。
- 键盘快捷键打开新增弹窗（如 Ctrl+K 搜索 / N 新增，避免与浏览器快捷键冲突）。
- 富文本编辑自动保存草稿或离开提醒；采用技术上可靠且低维护的方案。
- 响应式布局保证桌面为主的窄屏可用性。

### V1 明确不做
- 自动抓取第三方网页标题、描述、视频字幕或封面；自动爬取或登录抖音/知乎。
- AI 模型接入、自动分类、自动关联、语义问答、向量数据库、知识图谱。
- PDF/Excel/Word 项目文件管理、全文解析、OCR。
- 云端部署、多端实时同步、登录/多用户、移动端分享菜单。
- 公开网站、付费、社交、评论、浏览量和推荐算法。
- 多级树形分类（V1 领域扁平、自定义即可；专题收藏夹可扁平）。

## 3. 主要页面和交互

### 3.1 首页 / 全部收藏
- 页面顶部：产品标识、全局搜索、添加按钮、设置入口。
- 导航：全部、待整理、我的笔记、领域列表、专题收藏夹列表。
- 主要区域：分类筛选条 + 规则网格卡片，卡片呈现封面/默认封面、标题、简述、领域/标签摘要、内容类型。
- 鼠标点击卡片主体 → 站内详情；点击明确的外链图标 → 原网站新标签页（`noopener noreferrer`）。
- 卡片提供可发现的编辑入口；避免整张卡片点击直接跳走。
- 空状态提供创建入口；大批量数据至少实现合理分页或懒加载策略，避免一次渲染全部条目。

### 3.2 新建收藏 / 新建笔记
- `+` 按钮打开弹窗/抽屉，先选择「收藏网址」或「原创笔记」。
- 收藏网址：必填 URL 和标题；可选简介、封面图片、个人富文本笔记、多领域、多标签、多专题收藏夹；允许跳过分类进入待整理。
- 原创笔记：必填标题；不需要 URL；可有封面、简介、富文本正文、领域、标签、专题收藏夹。
- 不做联网元数据抓取；不能强制用户输入封面和摘要。
- URL 输入只允许有效 http/https；前端与后端双重验证。重复 URL 显示提醒，不默默覆盖。

### 3.3 卡片详情
- 展示封面、标题、简介、来源链接、所属领域/标签/专题和富文本笔记。
- 可编辑、删除、跳转来源；可点击领域与专题返回对应结果。
- 富文本安全渲染，防止脚本注入；外部链接安全打开。

### 3.4 分类、标签、专题
- 三个概念的产品含义：领域=长期知识方向；标签=细粒度检索关键词；专题收藏夹=围绕任务/问题组织的精选条目。
- 均可在 UI 中管理；避免技术上绑定固定领域枚举。
- 领域与专题的删除不能删除原始收藏；保留标签清理的明确提示。

### 3.5 设置和备份
- 数据存储路径与软件版本；备份导出、备份导入与恢复确认。
- 恢复前自动制作本地安全备份；校验附件清单；对于损坏包给出可理解错误并避免覆盖现有数据。

## 4. 视觉与交互规范

- 整体为现代简洁、轻量的资源导航站，优先内容可读性，而非复杂企业仪表盘。
- 统一卡片网格与封面比例；页面留白、有层次的字体比例、轻微边框或阴影、统一圆角、有限强调色。
- 无封面时采用类别图形/渐变/图标形成稳定视觉（不依赖请求外部占位图）。
- 桌面宽屏优先，窄屏自适应；中文内容优先且避免中英混排拥挤。
- 输入、保存、删除、搜索必须给出明确的成功、失败和空结果反馈。
- 笔记支持标题 H2/H3、粗体、斜体、无序/有序列表、普通段落、超链接、图片插入；图片必须真正在本地存储，不是临时 blob URL。
- 可参考成熟资源导航站的清晰层次，但不要复制具体商业网站的视觉资产。

## 5. 轻量技术方案

建议：React + TypeScript + Vite + Tailwind CSS；Node.js + Express（或者更少维护的等效方案）；SQLite；成熟开源富文本编辑器（例如 Tiptap 或等效）；本地文件夹储存封面及正文图片。技术栈可由 Codex 在实现前短暂评估兼容性后作小幅调整，但不得无故引入 Docker、外部云服务、账号系统或向量数据库。

- 正式使用时由单个 localhost 服务器提供构建后的前端和 API（如 `127.0.0.1:3000`）。只绑定环回地址，不向局域网或公网监听。
- `data/` 独立于代码及静态演示数据，禁止放入 Git，升级/重新安装不覆盖。
- SQLite：外键约束、数据迁移与必要索引；使用参数化 SQL 或可信 ORM，不能拼接用户输入构造 SQL。
- 数据模型可用统一 Entry（bookmark/note），及 Domain、Tag、Collection，三张多对多关系表；Asset（图片）、Migration / SchemaVersion；字段包括 id、type、title、url(nullable)、description、cover_asset_id、rich_text_content、status、created_at、updated_at。
- 富文本内容选择经过定义的 JSON 文档或经过严谨清理的 HTML 格式保存，必须可安全渲染并保持格式；搜索需要能检索纯文本抽取内容。
- 图片上传：限定常见图片 MIME 类型，验证真实文件内容、大小限制、随机内部文件名、避免路径穿越；删除引用时明确图片清理策略，不误删被其他条目使用的图片。
- 备份：SQLite 官方备份 API 或等效一致性快照，不直接复制正在写入的主库；将数据库和附件一起封装；备份清单包含版本/时间/文件信息；恢复验证并防止 Zip Slip 路径穿越。
- 安全：本地绑定、URL 校验、安全富文本处理、防不可信文件上传、明确浏览器访问来源策略；不因“本地单用户”就取消基本安全检查。

## 6. 开发交付结构及维护

建议根目录：
```
PersonalKnowledge/
  README.md
  AGENTS.md
  docs/
    PRODUCT.md
    DESIGN.md
    ARCHITECTURE.md
    ROADMAP.md
    HANDOFF.md
    CHANGELOG.md

  data/               # 个人库和附件，不进入 Git
  scripts/            # 启动、校验、备份等

```

- README：新机器安装步骤、依赖、启动和停止、备份/恢复、常见报错。
- AGENTS：进入项目先读 README、HANDOFF、相关文档；先查现状再修改；不清除 data、不覆盖现有库、不偷偷升级架构；变更需测试；工作完成更新 HANDOFF。
- PRODUCT：产品边界、用户路径、功能、禁止项与验收。
- DESIGN：视觉原则、卡片与编辑器布局规范。
- ARCHITECTURE：实际采用的技术、数据库模式、文件储存、API、扩展点、迁移策略。
- ROADMAP：仅列后续候选功能，不是当前待自动执行需求。
- HANDOFF：当前 Git 提交、完成/未完成、测试证据、已知缺陷、下一步。
- CHANGELOG：重要功能与数据结构变更，按实际发生日期记录。
- 文档须简洁真实，不为形式堆砌，不创建大量重复规则。允许 Codex 在不改变产品范围的情况下优化目录组织。
- 使用 Git 管理代码；`.gitignore` 应忽略 database、附件、备份、密钥；首次开发完成提交可复现基线。若无法推送远程，则不强求。

## 7. 未来扩展边界

### 可以在 V1 后添加
1. AI 生成候选标题/摘要/领域/标签，必须人工审核；不覆盖原始记录。
2. 知乎/抖音链接导入改进或合法可行的批量同步（先验证平台限制）。
3. 图片风格参考库：画廊视图和图片批量导入，复用 Entry + Asset 结构。
4. PDF/Excel 附件及项目经验模板：先加附件，不自动进行复杂解析。
5. 认知变化事件、知识关联、知识搜索问答：独立演进，不侵入基本收藏流程。
6. 可公开展示：需要明确的发布流程与真正的数据隔离、身份认证；不能只把 `is_public` 字段返回给公网客户端。
7. 手机访问和跨设备同步：需重新评估身份验证、部署和数据库方案。

### 扩展原则
- 现在建立可迁移、可备份的统一条目模型即可，不提前写未启用的 AI 适配层和云端同步服务。
- 当前数据永久优先；任何 schema 变化必须迁移、备份、验证。
- 后续功能小步迭代、自动化测试、按真实使用价值决定优先级。

## 10. 项目决策记录（2026-10-12）
- 初始范围从“综合 AI 知识与认知系统”收敛为“可视化资源收藏为主、个人知识笔记为辅”的网站。
