# 个人知识收藏馆 V1.7.1：全站体验重构总指令

项目目录：`D:\Projects\PersonalKnowledge`
基线参考：V1.7 提交 `9a0a810d3d4251f829c41a07eda43c94b7cdc288`；实际以开工时的 Git HEAD、数据库版本与 HANDOFF 为准。

## 一、任务与边界

这是一轮现有产品的**交互重构和页面整合**，不是重写业务系统。保留 V1.7 已交付的结构化内容、领域树、专题、标签、工具、JSON v1/v2 导入、AI 问答、AI 整理与人工审核、来源追溯、历史恢复、双向关联及局部知识地图。禁止因新设计图没有表现某功能就将其移除。

先审计 README、AGENTS、HANDOFF、ARCHITECTURE、TESTING、实际前后端代码与数据库；检查 Git 工作树与运行中的服务。复用旧组件、API、检索、Provider、备份机制，不要并行创造第二套内容存储或第二套操作语义。

现有正式数据保护优先：任何迁移先校验至少一份可恢复备份，数据库写入测试在隔离数据目录。不得清空现有知识、隐式删除、自动调用付费 API。对正式数据进行删除或不可逆处理必须请求用户确认。

## 二、总设计约束

**全站固定顶部一级导航**：首页、收集箱、知识库、AI 助手。侧栏也提供相同四个入口，二者切换一致、同步高亮；侧栏允许整体收起。左侧结构导航保留可折叠的**领域树（含子领域）与专题**，不要替换成一排扁平快捷入口。设置在侧栏底部并在顶栏提供快捷入口。不新增“常用视图”或其他未经确认的导航分组；若旧功能已有用户保存的数据，不删除数据，先做保留或迁移方案。

顶部只固定轻量全局导航，不固定大型标题、Hero、分类面板。全局新建按钮跨页面可用；默认直接打开**快速记录**。全局搜索与页面导航一致。不同页面可以使用不同主体布局，但全站应共享基础按钮、内容操作、保存反馈、删除语义和导航状态。

**统一内容身份**：首页、收集箱、知识库、专题与阅读器指向同一条记录；从收集箱完成整理只是改变处理状态，不创建副本。内容类型：笔记、网站收藏、工具、综合文档；来源、领域、专题、标签、状态与类型相互区分。

**设计图只表达视觉与交互意图**：不据此创建虚构内容数量、阅读进度、附件预览或分类。沿用现有视觉语言，优先整合布局和组件，不开展额外品牌设计和复杂设计系统重建。

## 三、分批开发

### A. 全局外壳与基础操作（先完成）

1. 顶部四个一级导航固定；左侧同名入口和领域/专题树；可折叠并保持状态。阅读时可收起左侧，不压缩正文。
2. 全局新建：打开小型快速记录窗口，输入文字或粘贴链接即可保存；标题、领域、标签都可选；可通过次级入口打开工具/综合文档新建及统一 JSON 导入。不得将 JSON 导入作为快速记录的默认流程。
3. 全站统一内容操作：编辑、单条置顶/取消置顶、软删除到回收站、恢复、更多操作；多选是附加模式。删除被引用的对象时清楚提示影响；回收站恢复应保持内容 ID 与可恢复关联。
4. 置顶是独立属性，与“最近更新/最近添加/标题”等排序共存。排序方式由用户选择，置顶内容默认排在普通内容之前；针对手动排序仅在确有意义的固定集合中提供，不强制给全库加入拖拽排序。
5. 页面进入详情和返回时尽可能保留查询、领域/专题筛选、排序、滚动与章节位置；支持可分享、可刷新、可新标签页打开的站内详情定位。
6. 创建/保存失败保留输入，明确提示保存状态；返回或关闭保护未保存的编辑。

### B. 首页与收集箱

**首页**使用已认可的高保真方案：首页任务工作台；首屏包含简单快速记录、继续阅读、待处理摘要、最近使用。界面中只展示有真实数据支撑的模块；“继续阅读”要有真实导航目标，不能伪造阅读进度。不额外添加“常用视图”、随机知识推荐或大幅封面占据主导。

**收集箱**回归快速保存 + 待处理队列：顶部极简输入，输入后保存；列表提供查看、整理/完成处理、稍后处理、删除、单项更多菜单。分类编辑作为选中记录后的次要步骤，复杂导入保持独立入口。不要照搬知识库的领域面板、完整类型筛选和大型多条件搜索。收集记录仍属于统一内容库，完成处理后不再列在待处理队列中，内容没有被复制或丢失。

### C. 知识库

1. 领域树、专题分组为结构化入口；多维筛选支持领域、专题、标签、类型、来源、状态。各维度按需展开，可组合，关闭某个筛选面板不等于清除正在生效的筛选；显示当前生效条件并提供明确重置。
2. 默认显示信息密度合适的列表，网格可切换；工具以名称/用途/打开入口为主，综合文档以标题/结构为主，网站收藏以来源/标题为主。
3. 排序与单条置顶可直接发现，更多菜单提供编辑、移动归属、删除；批量选择作为明确的次级操作。
4. 允许从列表快速预览详情或直接完整打开；返回保持原筛选和列表位置。统一领域和专题显示归属，不引入第二套知识目录树。

### D. 内容详情与阅读器

采用共用的详情外壳、保存/编辑/置顶/删除/来源/关联机制，但依内容类型显示适配布局：

- **普通笔记**：正文优先；简洁元数据；短笔记可原位编辑；支持来源、关联、历史。
- **网站收藏**：原链接与来源平台优先；原始摘录与个人批注明确分区；打开原文容易；网页失效时仍保留已有摘录。
- **工具详情**：工具名称、用途、访问或启动入口、经验记录、相关工具；短内容可在侧边预览中完成大部分操作。
- **综合文档**：章节大纲 + 正文为默认；来源/关联/AI 作为可切换的辅助面板。不要默认将全局侧栏、章节栏、来源栏全部展开导致正文过窄。章节锚点稳定，阅读位置可恢复。

内容列表 → 预览 → 完整阅读是可选路径而非强制三级流程。点击标题可直接完整阅读，预览动作独立提供。宽屏可多栏，窄屏自动退化为单栏和抽屉。阅读中引用、批注、知识关联与上下文 AI 不应强制离开当前内容；新增能力以复用现有组件为先，不为高保真视觉牺牲阅读和编辑可靠性。

AI 处理后的内容需要清晰区分原始资料、AI 总结、用户判断与待验证结论；不伪造无法落到原文的精确引用。涉及判断修正，应保留历史和证据。

### E. AI 助手、知识探索、设置

复用当前 V1.6/V1.7 知识问答、分类优化、跨范围整合、关系审核、成本提示、模拟 Provider 和图谱功能。统一全局布局和上下文入口，不重新实现 AI 引擎或关联数据库。

AI 助手与当前内容上下文衔接；完整审核和历史仍在 AI 助手内。知识探索保留一层/两层关系、类型筛选、列表替代视图和现有节点数量上限。设置合理分组 AI 服务、领域与专题管理、导入导出、数据备份和外观，不要把日常操作藏到设置。

## 四、实施与保护规则

- 各阶段可以自主连续实施与修复，不需要反复申请普通开发授权；提交阶段性结果并在最终交付点停止，不自动进入下一产品版本。
- 不改变基础数据语义来适应视觉稿。必要数据库变更必须有迁移、回滚、兼容与校验；旧业务数据必须完整保留。
- 不增添用户未批准的主导航、常用视图、资讯流、复杂自动化、推荐系统、语音模型或付费服务。
- 设计图中出现的虚构内容和统计只用于示意；真实 UI 必须由真实数据驱动。
- 官方/旧版 ChatGPT JSON 导入、工具访问链接、专题动态规则、来源与历史、七种知识关系等功能要回归验证。

## 五、最终验收：以个人实际使用为准

仅需一名用户进行关键真实任务验收，避免多人研究和不必要的大规模性能工程；自动回归仍必须充分覆盖旧能力。至少核验：

1. 从任意页面点击新建，十秒内可记录一条灵感，且无必填分类。
2. 灵感出现在收集箱，完成整理后不再显示于待处理队列，但仍在知识库且内容 ID 不变。
3. 在领域/专题组合筛选中找到内容，单条置顶、排序、编辑、删除、回收站恢复均可用。
4. 从知识库打开笔记、工具、网页收藏和综合文档，类型专属信息正确；返回时不丢筛选与章节位置。
5. 综合文档默认阅读宽度适宜，大纲可定位，来源/关联按需打开，引用跳转可靠。
6. AI 助手、知识地图、知识审核与 JSON v1/v2 导入功能没有回归。
7. 现有正式数据、附件、草稿、来源及使用量不变；可验证备份与恢复。
8. Windows 启停、真实 Edge、窄屏布局、类型检查、构建及自动化测试通过。

最后提供修改清单、页面截图、测试结果、未实现和未验证事项、Git SHA 和交接文档。明确哪些设计图被落实、哪些出于数据和交互安全而采取等效实现。
